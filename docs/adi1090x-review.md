**재생 속도**

이 장비의 Plymouth 0.9.5 script 플러그인은 기본 50Hz로 갱신한다. 원본 테마들은 SetRefreshRate를 지정하지 않고 Math.Int(progress / divisor) % count로 이미지를 선택한다. 따라서 통상 FPS는 50/divisor이며 실제 갱신 부하에 영향을 받는다. 근거: https://archive.ubuntu.com/ubuntu/pool/main/p/plymouth/plymouth_0.9.5+git20211018.orig.tar.xz 의 src/plugins/splash/script/plugin.c.

| 제수 | 테마 수 | 50Hz 기준 |
|---:|---:|---|
| 0.5 | 1 | 100 FPS 상당 |
| 1 | 6 | 50 FPS 상당 |
| 1.5 | 1 | 33.3333 FPS 상당 |
| 2 | 61 | 25 FPS 상당 |
| 3 | 9 | 16.6667 FPS 상당 |
| 4 | 1 | 12.5 FPS 상당 |
| 5 | 1 | 10 FPS 상당 |

- 61개 테마의 일반적인 제수 2는 25FPS다. 우리 앱의 기본값 30FPS를 그대로 적용하면 빨라진다.
- dark_planet(제수 1.5)은 원본에서 20ms/40ms 표시 간격이 섞인다. 균일한 33.333FPS는 근사치다. 50Hz 기준 표시 순서로 펼치면 240프레임으로 원래 주기를 보존할 수 있다.
- seal_3(제수 0.5, 323프레임)은 매 갱신마다 인덱스가 2씩 이동한다. 단순히 100FPS를 지정하는 대신 [2*k % 323] 순서로 323프레임을 배열하고 50FPS로 재생하면 50Hz 기준 순서를 보존할 수 있다.

**우리 앱과의 차이 및 제안**

- 원본은 progress-0.png부터 시작하며 우리 앱은 throbber-0001.png와 item.json을 사용한다. 폴더 복사만으로는 등록되지 않는다.
- 파일 이름과 메타데이터를 변환한다고 가정할 때, 원본 해상도/전체 프레임 수 그대로 기존 소스 검사(최대 1024×1024, 합계 RGBA 64MiB)를 통과하는 테마는 26개다. 나머지 54개는 축소 등의 전처리가 필요하다. 이 수치는 전체 기능 호환 판정이 아니다.
- hexagon(1080×1080), rog와 rog_2(1080×720)는 한 변 1024 제한도 넘는다. 가장 큰 polaroid는 392×800×600×4=717.77MiB의 프레임 버퍼를 요구한다. PNG 파일 용량과 디코딩 메모리는 다르다.
- 현재 스피너 크기 UI 상한은 320px다. 원본처럼 큰 중앙 애니메이션을 표현하려면 크기 정책을 별도로 설계해야 한다. 모든 테마를 160px로 축소하면 보수적인 정사각형 버퍼 계산에서도 프레임 수 제한/64MiB 안에 들어가지만 원본의 크기와 세부 표현은 달라진다.
- 모든 프레임이 불투명하므로 일반 투명 스피너처럼 배경색 변경을 보장할 수 없다. 검정을 일괄 투명화하면 그림 내부의 검정도 손상될 수 있다. 원본 배경을 유지하는 모드가 필요하다.
- 로고 숨김 옵션이 필요하다. 현재 앱은 사용자 로고와 스피너를 함께 표시하지만 이 저장소의 원본은 애니메이션 하나를 화면 중앙에 원본 크기로 표시한다.
- 원본 스크립트는 password 콜백에서 state.status="pause"를 설정하지만 refresh에서 이 값을 검사하지 않아 애니메이션이 계속 진행한다. 이는 Angular 런타임 검사에서도 확인했다. 업데이트 진행, hide-message, quit 콜백은 등록하지 않는다. 우리 앱의 기존 입력/메시지 처리를 유지하는 것이 유리하다.
- README의 update-initramfs -u나 showplymouth.sh를 가져오기 과정에서 실행하지 않는다. 우리 앱의 장비별 initramfs 생성·검사·백업·복원 경로를 사용하도록 연결해야 한다.
- 추천 구조: 외부 테마 읽기 → 스크립트가 실제 쓰는 프레임/순서/속도 검증 → 필요 시 축소 → 애니메이션 리소스로 등록 → 로고 표시 여부·배경·배치와 함께 사용자 프리셋 저장. seal_2는 프레임 누락을 명시하고 자동 승인하지 않는다.
